# Angular — Détail du samedi 6 juin 2026

## 1. Angular 22 — Migration communauté : TypeScript 6 obligatoire, OnPush uniquement CLI, httpResource stable

**Source :** Angular Addicts — https://www.angularaddicts.com/p/angular-addicts-48-typescript-6-on-push-as-default
**Date :** 5 juin 2026

### Contexte

Angular 22 est sorti le 3 juin. Trois jours après le GA, la communauté publie ses premiers retours de migration. Ninja Squad, Angular Addicts et AngularArchitects convergent sur les mêmes points de friction : le comportement de OnPush par défaut est plus ciblé que beaucoup l'avaient anticipé, et le prérequis TypeScript 6 constitue la vraie rupture opérationnelle pour les équipes.

### Ce qui change concrètement

**TypeScript 6 — rupture universelle :**
- `@angular/core` v22 requiert TypeScript ≥ 6.0, incompatible avec TS 5.x.
- Tout projet Angular doit mettre à jour `typescript` dans `package.json`, réviser les `tsconfig.json` (certaines options disparaissent, d'autres changent de valeur par défaut).
- La commande de migration automatique `ng update @angular/core` gère la plupart des ajustements, mais des ajustements manuels restent nécessaires pour les configs sur mesure.

**OnPush par défaut — nuance importante :**
- Les composants générés via `ng generate component` après la mise à jour utilisent automatiquement `ChangeDetectionStrategy.OnPush`.
- Les fichiers **existants** ne sont **pas modifiés** — ils gardent leur stratégie actuelle (Eager par défaut pour les anciens projets).
- Le schematic de migration (`ng update`) ne modifie pas non plus les fichiers existants ; c'est à l'équipe de migrer progressivement.

**httpResource stable :**
- L'API `httpResource()` quitte le statut expérimental. Elle expose un `Signal<T>` qui réagit aux changements de route, de paramètres ou de contexte sans subscription manuelle.
- Fonctionne en tandem avec `resource()` (pour les sources non-HTTP) pour couvrir l'ensemble des cas asynchrones réactifs.

**Node 20 supprimé, Node 26 recommandé :**
- Les CI/CD utilisant Node 20 doivent être mis à jour avant de monter Angular en v22.

### Pourquoi ça compte pour toi

Tu travailles probablement sur des projets Angular en place depuis plusieurs versions. La bonne nouvelle : OnPush par défaut ne touche pas ton code existant. La vraie action urgente est la montée en TypeScript 6 — teste d'abord sur une branche isolée, vérifie les erreurs de type nouvelles et les options de `tsconfig` dépréciées avant de merger. Si tu utilises `HttpClient` directement, commence l'évaluation de `httpResource` sur un endpoint simple.

### Points de vigilance

- Si ton pipeline CI était pinné sur Node 20, la montée en Node 26 peut introduire des incompatibilités dans des dépendances natives (addons npm C++). Valide en local avant.
- Les libs Angular tierces qui n'ont pas encore publié une version compatible TS 6 peuvent bloquer la migration — consulte la matrice de compatibilité de chaque lib.
