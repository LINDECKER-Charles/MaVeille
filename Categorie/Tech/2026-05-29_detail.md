# Tech — Détail du vendredi 29 mai 2026

## 1. PostgreSQL 18.4 — 11 CVE corrigées, dont fuite de timing MD5 et injection SQL logical replication

**Source :** PostgreSQL News — https://www.postgresql.org/about/news/postgresql-184-1710-1614-1518-and-1423-released-3297/
**Date :** 14 mai 2026

### Contexte

Release de routine pour les branches `18`, `17`, `16`, `15`, `14` — mais l'addition de 11 CVE en une seule release est inhabituelle, et plusieurs touchent des chemins d'authentification ou de réplication qui se retrouvent souvent en bord d'Internet. À noter : **PostgreSQL 14 perd son support le 12 novembre 2026** — si tu es encore dessus en prod, c'est ta dernière saison de patches.

### Ce qui change concrètement

- **MD5 password timing channel** : la comparaison du hash MD5 en authentification fuit du timing, permet la récupération de credentials suffisants pour authentifier un attaquant. **scram-sha-256 (défaut depuis longtemps) n'est PAS affecté.** Action : si tu as encore des rôles avec `password_encryption = md5`, migre.
- **SQL injection dans `ALTER SUBSCRIPTION ... REFRESH PUBLICATION`** : les noms de schéma et de relation étaient interpolés dans des commandes SQL sans quoting — un attaquant qui contrôle le publisher peut exécuter du SQL arbitraire sur le subscriber. Critique en réplication multi-org.
- **DoS via SSL/GSS negotiation** : récursion non contrôlée dans la négociation SSL et GSS, exploitable via socket AF_UNIX (et TCP si SSL+GSS désactivés). Tient le service en respiration artificielle.
- **Path traversal dans plusieurs binaires** : les binaires écrivaient le chemin de sortie sans valider l'input → écrasement de n'importe quel fichier writable par l'utilisateur PostgreSQL.
- **Multiples fixes contrib** : injections SQL secondaires, buffer overflows mineurs.
- **tzdata 2026b** : British Columbia passe en UTC-07 toute l'année (DST permanent) à partir de novembre 2026, correction historique pour Moldova.

### Pourquoi ça compte pour toi

Si tu gères du PostgreSQL en prod (perso ou pro), **patch immédiat** — la mise à jour est binary-only, pas de dump/reload nécessaire. Audite tes rôles : `SELECT usename, passwd FROM pg_shadow WHERE passwd LIKE 'md5%';` — si c'est non vide, force le passage à scram-sha-256 (`ALTER ROLE ... PASSWORD ...` avec `password_encryption = scram-sha-256` dans `postgresql.conf`). Si tu fais de la logical replication entre orgs, traite l'injection SQL comme une urgence.

### Points de vigilance

Plan PostgreSQL 14 EOL maintenant — la fenêtre se referme en novembre. Tester l'upgrade en staging avec ta version exacte d'extensions tierces (TimescaleDB, PostGIS, pgvector).

## 2. CISA KEV — TanStack, Nx Console et DAEMON Tools confirmés activement exploités

**Source :** CISA — https://www.cisa.gov/news-events/alerts/2026/05/27/cisa-adds-three-known-exploited-vulnerabilities-catalog
**Date :** 27 mai 2026

### Contexte

Le Known Exploited Vulnerabilities catalog (KEV) de la CISA liste les vulnérabilités pour lesquelles l'exploitation active est confirmée. Trois ajouts d'un coup, tous supply-chain, c'est très inhabituel — et les trois touchent directement les développeurs. Cette session du digest du 27 mai (déjà rapportée dans le digest du 27/28) avait analysé l'attaque Nx Console ; aujourd'hui c'est la **confirmation officielle CISA** qui change le statut en obligation de patch pour les agences fédérales US et accélère le triage côté privé.

### Ce qui change concrètement

- **CVE-2026-45321 — TanStack Unspecified (CVSS 9.5)** : 84 versions npm publiées sous l'identité légitime de TanStack via combinaison de **cache poisoning**, **misconfiguration `pull_request_target`** dans GitHub Actions et **vol de token OIDC** depuis la mémoire du runner. Le malware embarqué exfiltre des credentials (npm, env, AWS) vers serveurs C2.
- **Nx Console (extension VS Code)** : la fausse extension publiait des binaires malveillants distribués au sein du marketplace, déjà couvert dans le digest du 27/05.
- **DAEMON Tools Lite (CVE-2026-8398)** : embedded malicious code dans l'installer Windows distribué officiellement.

### Pourquoi ça compte pour toi

Action concrète pour aujourd'hui : `npm audit signatures` sur tes lockfiles, recherche des versions TanStack listées dans l'advisory officiel, et `npm ci --ignore-scripts` si tu n'as pas confiance dans tes builds CI. Pour Nx Console : désinstaller depuis VS Code, vérifier les credentials qui étaient stockés (`gh`, `npm token`, `azure cli`). Réémettre ces tokens en cas de doute. C'est aussi un argument fort pour exiger `OIDC ID token` audience scoping strict dans tes workflows GitHub Actions.

### Détails techniques

Pattern récurrent en 2026 : compromission de pipeline CI via `pull_request_target` mal configuré. Le runner reçoit les secrets du repo principal mais exécute du code d'une PR externe — un attaquant ouvre une PR, force l'exécution du workflow, exfiltre l'OIDC token, et l'utilise pour publier sur npm. **Mitigation** : `permissions: read-all` par défaut, `id-token: write` uniquement quand strictement nécessaire, et `workflow_dispatch` plutôt que `pull_request_target` pour les checks risqués.

## 3. bzip2 CVE-2026-42250 — Off-by-one dans bzip2recover, OOB write

**Source :** CERT Polska — https://cert.pl/en/posts/2026/05/CVE-2026-42250/
**Date :** 28 mai 2026

### Contexte

`bzip2` reste embarqué partout (paquets `.deb`, archives `.tar.bz2`, drivers kernel, builds système). Le binaire `bzip2recover` extrait des blocs depuis une archive corrompue. Un off-by-one dans son parsing permet à un fichier `.bz2` forgé de déclencher un OOB write sur un buffer global, ce qui plante le binaire (DoS) — pas d'exécution code arbitraire démontrée pour l'instant.

### Ce qui change concrètement

- **Toutes les versions < 1.0.9** sont affectées (1.0.9 publié simultanément avec le fix).
- **CWE-787** (Out-of-bounds Write).
- Fix dans le commit `35d122a3df8b0cc4082a4d89fdc6ee99f375fe67`.
- Reporters : Michał Majchrowicz et Marcin Wyczechowski (AFINE Team).

### Pourquoi ça compte pour toi

Si tu pipes du contenu utilisateur dans `bzip2recover` (récupération automatique de backups, parsing d'archives uploadées), traite ça comme une vuln à patcher. Sur tes builds Docker, force `apt-get install bzip2=1.0.9-*` quand ta distro la publiera — Debian / Ubuntu vont republier dans les heures qui suivent. Surveille `apt list --upgradable | grep bzip`.

### Limites

Impact réel modéré — DoS uniquement à ce stade, pas d'exécution code. Mais la fonction touchée est appelée par des tooling automatiques (rotation de logs, ingestion), donc le risque opérationnel est réel.

## 4. Stack Overflow Developer Survey 2026 — Copilot tombe à 51%, Cursor passe $2B ARR

**Source :** Stack Overflow Developer Survey (récap) — https://pasqualepillitteri.it/en/news/3392/github-copilot-cursor-claude-code-ai-coding-showdown-2026
**Date :** mai 2026

### Contexte

Le Stack Overflow Developer Survey 2026 vient de tomber, premier instantané sérieux sur l'usage réel des assistants IA depuis l'irruption de Cursor et Claude Code. Les chiffres cassent le narratif « Copilot a déjà gagné » qui dominait fin 2025.

### Ce qui change concrètement

- **GitHub Copilot : 51 %** d'adoption chez les devs pros (vs 67 % en 2025). Première baisse en chiffres absolus.
- **Cursor : 18 %** à sa première apparition standalone — il était dans « autres » l'an dernier.
- **Claude Code : 10 %** à sa première apparition.
- **Cursor ARR** : $100M jan 2025 → $500M juin → $1B novembre → **$2B février 2026**. Record absolu B2B SaaS — aucune autre boîte n'a atteint $2B ARR en moins de 24 mois depuis le lancement commercial.
- **Copilot agent mode** : amélioration significative début 2026 — crée des fichiers, écrit du code, lance des commandes terminal, fix les erreurs en autonomie. Première vraie réponse à Cursor / Claude Code côté GitHub.
- **Cursor marketplace** : depuis mars 2026, distribution d'extensions privées internes pour les enterprise customers.

### Pourquoi ça compte pour toi

Si tu choisis l'outil pour ton équipe, l'écart d'adoption se resserre — l'argument « Copilot car standard » ne tient plus seul. Test concret recommandé : monter une feature en parallèle sur les trois sur 2 jours (Copilot avec agent mode activé, Cursor, Claude Code), comparer sur ton stack réel. Le différenciateur n'est plus la qualité brute des suggestions mais l'**agent mode** (compréhension multi-fichiers, exécution terminale, debug en boucle).

### Limites

Le Stack Overflow Survey a un biais selection (réponses volontaires, surreprésentation devs web). Et l'ARR Cursor de $2B reste à confirmer comme cash receivable vs bookings — chiffre maison non audité.
