# IA — Détail du samedi 30 mai 2026

## 1. vLLM 0.21.0 — DeepSeek V4 stabilisé sur Blackwell

**Source :** vLLM Releases (GitHub) — https://github.com/vllm-project/vllm/releases
**Date :** 15 mai 2026

### Contexte

`vLLM` 0.20.0 avait introduit le support de **DeepSeek V4** (architecture MoE 1,6T multimodale, déjà couvert). La 0.21.0 est la release de **stabilisation** qui rend ce support réellement production-grade sur le matériel NVIDIA **Blackwell**.

### Ce qui change concrètement

- DeepSeek V4 réorganisé dans un package dédié `vllm/models/deepseek_v4/`, avec **NVFP4 fused MoE**, CUDA graph complet + piecewise, et **MTP speculative decoding**.
- Nouveau backend **`TOKENSPEED_MLA`** ; le speculative decoding respecte désormais les budgets de raisonnement.
- **KV Offload** intégré au **Hybrid Memory Allocator** : sur des modèles hybrides qui gaspillaient jusqu'à ~80 % de la capacité KV-cache, le gain de débit est concret.
- Story production-grade étendue à Kimi K2.6 et Cohere MoE sur Blackwell.

### Pourquoi ça compte pour toi

Si tu envisages d'auto-héberger un gros modèle derrière une API .NET ou Symfony, c'est la version qui rend DeepSeek V4 exploitable sans bricolage. Le KV Offload change ton calcul de coût VRAM : tu peux viser moins de GPU pour le même contexte. Reste sur Blackwell pour profiter du NVFP4.

### Limites

- EAGLE 3.1 (long-context speculative decoding fiable) n'arrive qu'en 0.22.0 : pour du très long contexte, attends.

## 2. Runtimes locaux mai 2026 — la vague MTP (Ollama 0.24, llama.cpp, MLX, LM Studio)

**Source :** Codersera — https://codersera.com/blog/local-ai-runtimes-may-2026-update/
**Date :** mai 2026

### Contexte

Tous les runtimes locaux majeurs ont publié ce mois-ci, avec un thème commun : le **multi-token prediction (MTP)** / speculative decoding passe en stable, et le support matériel récent (Blackwell, Apple M5) se généralise.

### Ce qui change concrètement

- **Ollama** : passage 0.23 → 0.24 en 11 jours. Support de l'app **Codex**, **Gemma 4 MTP speculative decoding** via le runner MLX, sampler MLX retravaillé.
- **llama.cpp** : support **Qwen 3.6 MTP** mergé, prebuilts **Windows CUDA 13.1** (build b9196).
- **MLX** : 0.31.x + macOS 26.2 débloquent les **Neural Accelerators du M5**, jusqu'à 4× plus rapide en TTFT.
- **LM Studio** : 0.4.13 ajoute les prédictions vision parallèles ; 0.4.14 promeut le MTP speculative decoding en stable.

### Pourquoi ça compte pour toi

Pour prototyper en local sans cloud, le MTP stable divise la latence perçue : un assistant de code local devient utilisable au quotidien. Sur Windows, les prebuilts CUDA 13.1 de llama.cpp t'évitent une compilation pénible. Choisis Ollama pour la simplicité, llama.cpp si tu veux contrôler finement le GPU.

### Points de vigilance

- Le speculative decoding gagne en débit mais demande un modèle « draft » compatible : vérifie la disponibilité avant de l'activer.
