# IA — Synthèse du dimanche 23 août 2026

## Digest court

Pas de nouveaux poids ouverts ce week-end : le Hub de Hugging Face n'a rien publié depuis le 21 août. Le sujet du jour est ailleurs, et il est plus intéressant — comment on mesure et on encadre des agents qui touchent du vrai. AWS publie `aws-bench`, un benchmark open source qui n'évalue plus les agents sur des fixtures figées mais sur des ressources AWS réellement provisionnées dans des comptes jetables, avec des vérificateurs qui inspectent l'état live. LinkedIn, de son côté, détaille une plateforme de revue de code multi-agents et publie ses chiffres : 63,9 % de suggestions acceptées sur 5 230 commentaires. Les deux histoires convergent sur la même leçon : ce qui coûte cher, ce n'est pas de générer, c'est de vérifier.

## Top 1 — `aws-bench` : évaluer un agent sur du vrai, pas sur une fixture

- **Comptes jetables** : chaque scénario est déployé via des stacks CDK dans des comptes AWS isolés, l'agent travaille dans un conteneur sandboxé avec des credentials à portée réduite.
- **Vérification** : notation par juge LLM ou par contrôle programmatique de l'état AWS réel.
- **Périmètre** : observabilité, compute et data, bases et stockage, EC2 multi-région, serverless, streaming et IoT, dépannage multi-services.
- **Bâti sur Harbor** : adaptateurs prêts pour Claude Code, Codex, Kiro CLI et Mini-SWE-Agent, plus tout agent déjà supporté par Harbor.
- **Ce qui manque au lancement** : aucun résultat de référence ni leaderboard publié, les deux sont sur la feuille de route.

## Top 2 — LinkedIn : la revue de code IA traitée comme de l'infrastructure de production

- **Plusieurs relecteurs, pas un** : des agents indépendants avec des modèles et des approches de raisonnement distincts, pour ne pas hériter des angles morts d'un modèle unique.
- **Personnalisation à trois niveaux** : politiques d'organisation, conventions par dépôt, règles contextuelles — composables.
- **Validation croisée** : la convergence de plusieurs agents sur un même problème vaut preuve forte ; un signalement isolé est vérifié séparément, pas jeté.
- **Chiffres** : 5 230 commentaires sur 1 727 pull requests, 90,1 % évaluables avec une confiance élevée, 63,9 % de suggestions acceptées au global.
- **Par catégorie** : 100 % des bugs de concurrence, 80 % des erreurs de logique, 58,1 % des corrections de bugs, 43,5 % des refactorings, 40,6 % des correctifs de sécurité.
