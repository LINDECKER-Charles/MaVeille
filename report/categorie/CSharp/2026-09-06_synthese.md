# CSharp — Synthèse du samedi 6 septembre 2026

## Digest court

Un seul sujet cette semaine sur le blog .NET, mais c'est un vrai changement de posture sur les tests. Depuis **MSTest 4.4**, tu peux publier et exécuter un projet de tests en **Native AOT**, grâce à un générateur de source qui enregistre à la compilation quelles classes de test existent et comment les invoquer — avant que le trimming ne passe. L'argument n'est pas la performance : c'est la fidélité. Une passe de tests managés verte ne dit rien de ce qui se passe une fois l'application trimmée et compilée en avance de phase. Le mot d'ordre de Microsoft est explicite : *test what you ship*. Côté cycle, rien de neuf : .NET 11 reste en preview, GA attendue en novembre 2026.

## Top 1 — MSTest 4.4 : tester sous le modèle de déploiement que tu livres

- **`PublishAot=true` + `MSTest.Sdk/4.4.0`** : deux lignes de csproj suffisent à activer la génération de source et le chemin d'exécutable natif.
- **Ce que le générateur émet** : un registre des classes de test, les données d'attributs, des délégués de construction et d'invocation, et les références qui préservent tout ça au trimming.
- **Le modèle de programmation ne bouge pas** : tes `[TestClass]` et `[TestMethod]` restent des `[TestClass]` et `[TestMethod]`.
- **Ce que ça démasque** : sérialisation `System.Text.Json` par réflexion désactivée, génération de code au runtime, métadonnées de réflexion absentes, dépendance incompatible.
- **Limites à connaître** : classe qui *hérite* seulement de `[TestClass]`, type inaccessible / `file`-local / statique / générique ouvert, méthode générique ou à paramètres `ref`/`out`/`in`.

## Top 2 — Ce que ça change dans ta CI

- **Deux voies, pas une** : garde la passe managée rapide pour la boucle de feedback, ajoute une voie « publish + run natif » sur **un seul** projet représentatif.
- **La parité du nombre de tests est un gate de release** : une classe exclue du registre peut faire passer un sous-ensemble en silence, avec un code de sortie 0.
- **Mode de repli** : `MSTestSourceGenMode=Rooting` préserve les membres découverts mais garde l'exécution réflective — utile pour instruire une incompatibilité.
- **Migration préalable** : les projets encore sur VSTest doivent passer à Microsoft Testing Platform.
