# CSharp — Synthèse du lundi 21 septembre 2026

## Digest court

Rien de neuf sur le blog .NET depuis mardi : le cycle est en phase RC et l'équipe garde ses annonces pour la GA du 10 novembre. En revanche les notes de version d'EF Core 11 contiennent deux évolutions que tu peux tester dès aujourd'hui avec la licence go-live du RC1. La première comble un trou de LINQ vieux de dix ans : le `FULL OUTER JOIN`. La seconde débloque une limite agaçante du modèle : indexer une propriété qui vit à l'intérieur d'un complex type. Les deux touchent directement ton usage PostgreSQL et SQL Server.

## Top 1 — `Queryable.FullJoin` : le FULL OUTER JOIN arrive enfin en LINQ

- **L'opérateur** : `FullJoin` complète `LeftJoin` et `RightJoin` arrivés en .NET 10, et se traduit en `FULL OUTER JOIN` natif.
- **Le gain** : plus de `Union` entre deux requêtes ni d'évaluation côté client pour réconcilier deux ensembles.
- **En bonus** : EF Core génère désormais `NULLIF(col, const)` au lieu d'un `CASE WHEN`, et supprime les `CASE ... IS NOT NULL` redondants.

## Top 2 — `HasIndex` traverse les complex types, et les index JSON sur SQL Server

- **Ce qui change** : `HasKey`, `HasAlternateKey` et `HasIndex` acceptent des chemins pointés du type `c => c.Address.ZipCode`.
- **Effet de bord** : les propriétés utilisées dans une clé ou un index deviennent automatiquement obligatoires, ainsi que les complex types du chemin.
- **SQL Server** : les index peuvent désormais se poser sur des propriétés situées à l'intérieur d'une colonne mappée en JSON.
- **Migrations** : un changement de facette d'index émet un unique `CREATE INDEX ... WITH (DROP_EXISTING = ON)` au lieu d'un couple `DROP` puis `CREATE`.
