# CSharp — Synthèse du vendredi 25 septembre 2026

## Digest court

Deux sujets très concrets, et le premier demande une action de ta part. Microsoft a **changé le certificat de signature auteur** de ses paquets NuGet depuis le 23 septembre : si ton `nuget.config` épingle des empreintes de signataires de confiance, tes restores vont casser avec un `NU3034` dès qu'un paquet Microsoft fraîchement signé arrive. Le second sujet est un pas-à-pas pour **capturer un dump mémoire depuis ton propre process**, avec une sonde de saturation du thread pool comme déclencheur — utile quand ton app ne plante pas mais se fige.

## Top 1 — NuGet : nouvelle empreinte de signature Microsoft

- **Date d'effet** : dès le 23 septembre 2026, les nouveaux paquets Microsoft sont signés avec le certificat `9A1B131B…FEB630`.
- **Qui est touché** : uniquement ceux qui utilisent `signatureValidationMode=require` avec une allowlist `trustedSigners`, ou `dotnet nuget verify --certificate-fingerprint`.
- **Symptôme** : erreur **NU3034** à l'installation d'un paquet signé avec le nouveau certificat.
- **Correctif** : `dotnet nuget trust author Microsoft <nouvelle empreinte> --algorithm SHA256`, **sans retirer** les anciennes.

## Top 2 — Capturer un dump mémoire depuis C#

- **Sonde thread pool** : un thread dédié poste périodiquement une `Task` triviale et chronomètre son temps de démarrage. Dépassement de seuil = pool saturé.
- **Windows** : P/Invoke sur `MiniDumpWriteDump` de `dbghelp.dll`, avec les flags `WithFullMemory` et compagnie (~125 Mo dans l'exemple).
- **Linux** : l'utilitaire `createdump` livré avec le runtime, plus un `prctl(PR_SET_PTRACER)` pour contourner Yama en conteneur (~800 Mo).
- **Pièges signalés en commentaires** : `LibraryImport` > `DllImport` en .NET moderne, et `MiniDumpWriteDump` sur son propre process peut deadlocker.
