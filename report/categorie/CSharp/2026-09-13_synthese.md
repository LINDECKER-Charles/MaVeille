# CSharp — Synthèse du dimanche 13 septembre 2026

## Digest court

Deux sujets d'exploitation, pas de langage, ce week-end. D'un côté AWS étend **Lambda SnapStart aux images de conteneur** : le compromis « 10 Go de dépendances ou démarrage sub-seconde » disparaît, et les images de base **.NET 8+** fonctionnent comme un zip. De l'autre, la release de servicing **.NET de septembre** corrige **huit CVE** sur .NET 10, 9 et 8, dont une qui touche aussi .NET Framework 4.6.2 à 4.8.1. Les deux sujets se rejoignent sur un même point aveugle : quand tu passes au conteneur, **le patch du runtime devient ta responsabilité**, pas celle d'AWS ni de Microsoft.

## Top 1 — Lambda SnapStart arrive sur les images de conteneur

- **10 Go contre 250 Mo** : le plafond du conteneur, désormais sans pénalité de démarrage. AWS annonce du sub-seconde.
- **Images de base AWS .NET 8+** (comme Java 11+ et Python 3.12+) : expérience identique au zip, rien à faire.
- **Toute autre base** doit ajouter `LABEL com.amazonaws.lambda.feature.snapstart="Allow"` ou implémenter les runtime hooks. Sinon la publication de version **échoue à l'initialisation**.
- **Hooks .NET** : `RegisterBeforeSnapshot()` et `RegisterAfterRestore()` — indispensables pour les pools de connexions, les secrets et l'aléa.
- **Limites** : stockage éphémère > 512 Mo incompatible ; indisponible en Asie-Pacifique (Nouvelle-Zélande, Taipei) ; tarification SnapStart séparée.

## Top 2 — Servicing .NET de septembre : huit CVE, deux chaînes d'approvisionnement

- **.NET 10.0.12, 9.0.20, 8.0.31** publiés le 8 septembre.
- **CVE-2026-69805, 69439, 71328, 69522, 69304, 58649, 66822, 69806** corrigées.
- **CVE-2026-69522** déborde sur **.NET Framework 4.6.2 → 4.8.1** — un périmètre à ne pas oublier si tu traînes du legacy.
- **`dotnet list package --vulnerable` ne voit pas le runtime** : il audite tes paquets NuGet, pas le framework sous tes pieds. Ce sont deux chaînes distinctes.
- **Self-contained et conteneurs** : pas de patch automatique, il faut **republier** ou rebâtir l'image.
