# Tech — Détail du samedi 20 juin 2026

## 1. NGINX HTTP/3 — CVE-2026-42530 : use-after-free corrigé en urgence par F5

**Source :** The Hacker News — https://thehackernews.com/2026/06/f5-patches-two-critical-nginx-open.html
**Date :** 18 juin 2026

### Contexte

F5 a publié des correctifs hors-cycle (out-of-band) pour deux failles critiques de NGINX Open Source : `CVE-2026-42530` et `CVE-2026-42055`. La première touche le module HTTP/3 `ngx_http_v3_module`, activé dès que tu sers du QUIC. C'est rare : NGINX patche rarement en urgence hors de son cycle habituel.

### Ce qui change concrètement

- **Mécanisme** : une session HTTP/3 forgée rouvre un flux d'encodeur QPACK, ce qui provoque un *use-after-free* dans le worker NGINX.
- **Impact** : crash et redémarrage du worker (déni de service) ; **exécution de code possible** si l'ASLR est désactivé ou contournable.
- **Scoring** : CVSS 8.1 (v3.1), porté à **9.2 en CVSS v4**. Attaquant distant, non authentifié.
- **Versions** : 1.31.0 à 1.31.1 vulnérables ; **corrigé en 1.31.2**.
- **Mitigation immédiate** : retirer `quic` de toutes les directives `listen` (désactive HTTP/3).

### Pourquoi ça compte pour toi

Si tu exposes une API ou un front derrière NGINX avec HTTP/3 activé, tu es directement concerné. Vérifie ta version (`nginx -v`) et tes `listen ... quic`. Passe en 1.31.2+ ou coupe QUIC le temps du patch. Le risque réaliste est un DoS de ta passerelle ; le RCE reste conditionnel mais sérieux.

### Points de vigilance

HTTP/3 est souvent activé sans qu'on s'en souvienne (templates, reverse-proxy managé). Audite aussi tes images Docker NGINX : beaucoup figent une version. Référence éditeur : [F5 K000161616](https://my.f5.com/manage/s/article/K000161616).

## 2. Splunk CVE-2026-20253 — RCE pré-auth via le sidecar PostgreSQL, déjà exploitée

**Source :** BleepingComputer — https://www.bleepingcomputer.com/news/security/cisa-splunk-enterprise-flaw-actively-exploited-patch-by-sunday/
**Date :** 18 juin 2026

### Contexte

Splunk a divulgué `CVE-2026-20253` (avis SVD-2026-0603) le 10 juin. La faille vise le **service sidecar PostgreSQL** embarqué dans Splunk Enterprise. Depuis, la situation s'est aggravée : PoC public watchTowr le 12 juin, exploitation observée à partir du 15, puis **ajout au catalogue CISA KEV le 18 juin** avec une échéance de remédiation très courte (dimanche).

### Ce qui change concrètement

- **Nature** : création/troncature de fichiers arbitraires **non authentifiée** (CVSS 9.8).
- **Chaîne RCE** : les endpoints de backup/restore exposés sans auth permettent, via `lo_export` de PostgreSQL, d'écrire un script puis de l'exécuter. S'y ajoutent du path traversal et un traitement non sûr de paramètres PostgreSQL.
- **Versions** : 10.0.0–10.0.6 et 10.2.0–10.2.3 ; **corrigé en 10.2.4 / 10.0.7**.
- **Exposition** : Splunk Enterprise sur **AWS est vulnérable par défaut** ; les installs Windows manuelles n'ont souvent pas le sidecar.

### Pourquoi ça compte pour toi

Deux raisons. Si tu opères un Splunk, patche **maintenant** : l'exploitation est active et l'échéance CISA est ce week-end. Plus largement, c'est un cas d'école qui te concerne en tant qu'utilisateur PostgreSQL : `lo_export` et les *large objects* transforment une écriture de fichier en RCE. Vérifie que tes rôles applicatifs n'ont pas ces privilèges.

```csharp
// Audit rapide (Npgsql) : le rôle applicatif est-il superuser / a-t-il les droits large objects ?
await using var conn = new NpgsqlConnection(connectionString);
await conn.OpenAsync();

await using var cmd = new NpgsqlCommand(
    "SELECT rolsuper, rolbypassrls FROM pg_roles WHERE rolname = current_user", conn);
await using var r = await cmd.ExecuteReaderAsync();

if (await r.ReadAsync() && (r.GetBoolean(0) || r.GetBoolean(1)))
    throw new InvalidOperationException(
        "Le rôle applicatif est trop privilégié : lo_export/lo_import exploitables.");
```

### Détails techniques

La primitive d'écriture seule suffit déjà à compromettre la configuration. Voir l'analyse [watchTowr / Orca Security](https://orca.security/resources/blog/cve-2026-20253-splunk-enterprise-rce-unauthenticated-file-operations/) et l'entrée [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog).
