## 1. Langflow CVE-2026-5027 — RCE non authentifiée sur la plateforme IA, exploitée et non patchée

**Source :** The Hacker News — https://thehackernews.com/2026/06/unpatched-langflow-flaw-cve-2026-5027.html
**Date :** 10 juin 2026

### Contexte

Langflow, plateforme open-source de construction d'apps LLM (flows visuels), est sous **exploitation active**. VulnCheck a ajouté `CVE-2026-5027` à sa liste KEV le 8 juin après détection in-the-wild par ses capteurs Canary.

### Ce qui change concrètement

- **CVSS 8.8** : path traversal dans l'endpoint `POST /api/v2/files`. Le paramètre `filename` du multipart n'est pas assaini → écriture de fichier arbitraire → **RCE sans credentials**.
- Surface aggravée par le défaut de Langflow : **auto-login non authentifié activé**. Une seule requête HTTP suffit à obtenir un token de session valide.
- **~7 000 instances exposées** sur Internet (requête Censys de VulnCheck), concentrées en Amérique du Nord. Les attaques observées écrivent des fichiers de test — précurseur classique d'un payload destructeur.

### Pourquoi ça compte pour toi

Si une équipe a déployé Langflow pour prototyper des chaînes LLM, considère-le comme compromis jusqu'à preuve du contraire. Sors-le immédiatement d'Internet (VPN/allow-list), coupe l'auto-login, et audite les fichiers écrits récemment. Le pattern « outil IA exposé + défaut non authentifié » se répète : applique le même réflexe à tout dashboard d'IA interne.

### Points de vigilance

Au 10 juin, **pas de correctif disponible** : la mitigation est réseau, pas applicative ([BleepingComputer](https://www.bleepingcomputer.com/news/security/path-traversal-flaw-in-ai-dev-platform-langflow-exploited-in-attacks/)).

## 2. Node-gyp — attaque supply-chain npm via `binding.gyp` exécuté à l'installation

**Source :** Snyk — https://snyk.io/blog/node-gyp-supply-chain-compromise-self-propagating-npm-worm-binding-gyp/
**Date :** juin 2026

### Contexte

Snyk suit une compromission supply-chain visant l'écosystème `node-gyp` : **57 paquets** affectés, des centaines de versions malveillantes. Elle s'ajoute à la vague npm de juin (après Miasma/Red Hat début juin).

### Ce qui change concrètement

- Vecteur : un fichier **`binding.gyp` piégé** déclenche l'exécution de code attaquant **pendant `npm install`** (phase de build native), avant même que tu lances ton app.
- Payload : vol de credentials **dev et CI/CD** — npm, GitHub, AWS, GCP, Azure, HashiCorp Vault, Kubernetes.
- Caractère **auto-propagateur** (worm) : un poste infecté republie des versions piégées.

### Pourquoi ça compte pour toi

C'est l'attaque la plus directe pour toi cette semaine. Tout `npm install` — local ou en pipeline — peut exfiltrer tes secrets cloud et tes tokens. Active `--ignore-scripts` par défaut, épingle tes versions (lockfile + `npm ci`), et fais tourner tes builds dans des conteneurs éphémères sans secrets longue durée. Vérifie aussi qu'aucun token npm/GitHub n'a fuité côté CI.

### Détails techniques

Le build natif Node (gyp) est un angle mort classique : il exécute du code arbitraire par conception. Les rotations de credentials AWS/Azure/Vault sont la première action si tu as installé des paquets suspects récemment.

## 3. Agentjacking — un faux bug Sentry détourne ton agent de code (injection MCP)

**Source :** The Hacker News — https://thehackernews.com/2026/06/agentjacking-attack-tricks-ai-coding.html
**Date :** 12 juin 2026

### Contexte

Tenet Security décrit **Agentjacking**, une nouvelle classe d'attaque : un **faux rapport d'erreur Sentry** suffit à faire exécuter du code arbitraire par un agent de code IA sur la machine du dev.

### Ce qui change concrètement

- Faille d'architecture à l'intersection de **l'ingestion Sentry** (qui accepte des payloads de quiconque a le DSN) et du **serveur MCP Sentry** (qui renvoie ces données à l'agent comme sortie système de confiance).
- Quand l'agent interroge Sentry pour les erreurs non résolues, il **ne peut pas distinguer** un vrai crash d'un événement injecté — et agit dessus.
- PoC : exfiltration de variables d'env, credentials AWS, tokens OAuth GitHub/GitLab, tokens npm, config Docker, tokens Kubernetes, secrets CI/CD.
- **2 388 organisations** identifiées avec des DSN injectables ; **85 %** de réussite sur 100+ organisations testées.

### Pourquoi ça compte pour toi

Tu utilises sûrement MCP et un agent de code. Le danger : tout contenu externe avalé par un serveur MCP (tickets, erreurs, issues) devient une **surface d'injection de prompt** que l'agent traite comme fiable. Traite les sorties MCP comme des entrées utilisateur non fiables, restreins les DSN Sentry, et n'autorise pas l'agent à exécuter des commandes sans validation humaine.

### Limites

L'attaque **contourne EDR, WAF, IAM, VPN et firewall** : chaque action est techniquement autorisée. La défense est architecturale (cloisonnement des outils MCP), pas périmétrique ([Tenet Security](https://tenetsecurity.ai/blog/agentjacking-coding-agents-with-fake-sentry-errors/)).
