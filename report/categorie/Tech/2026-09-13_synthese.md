# Tech — Synthèse du dimanche 13 septembre 2026

## Digest court

Trois sujets, un fil rouge : **la confiance dans ce qu'on n'a pas construit soi-même**. La CISA a ajouté à son catalogue KEV **CVE-2026-59822**, un contournement d'authentification dans l'endpoint MCP de **LiteLLM** — la première faille MCP à y entrer, exploitée, avec des dizaines de milliers de passerelles exposées sur Internet. Google, de son côté, a réécrit **tous les liens de ses résultats organiques** en redirections `google.com/goto` dont le jeton est chiffré : impossible de lire une destination sans passer par Google. Et **HashiCorp Packer 1.16** apporte la génération et la vérification natives d'attestations **SLSA** pour les images machine — la couche que la supply chain avait laissée de côté.

## Top 1 — CVE-2026-59822 : la première faille MCP au catalogue KEV

- **LiteLLM < 1.84.0** : le handler d'auth MCP remplace une validation de clé échouée par un objet `UserAPIKeyAuth()` **vide**.
- Un **Bearer token fabriqué** suffit alors à ouvrir une session MCP authentifiée, lister et appeler les outils configurés.
- **CVSS 8,8** sur la plupart des bases (certaines la cotent 8,2). **Exploitation active confirmée**.
- **80 600+ surfaces LiteLLM** exposées sur Internet, selon un relevé FOFA.
- **Correctif : 1.84.0**, qui rétablit le gating du fallback OAuth2.

## Top 2 — `google.com/goto` : les URLs de résultats deviennent opaques

- Déploiement silencieux **fin août 2026**, testé depuis juillet, proche de **100 %** des résultats.
- Chaque lien passe par une redirection serveur encodant la cible en **Protobuf chiffré Tink** (`?url=CAES…`) : **indécodable en local**.
- Google l'assume comme **mesure anti-abus** contre le scraping de ses résultats, y compris par les moteurs IA.
- **SerpApi** a déployé un correctif le **5 septembre** pour restituer les adresses réelles.
- Casse mécaniquement le rank tracking, le reporting SEO et tout parsing qui lisait `href` directement.

## Top 3 — Packer 1.16 : la provenance SLSA descend au niveau de l'image machine

- Nouveau post-processor **`provenance`** : énoncés **in-toto** avec prédicat **SLSA Provenance v1**.
- Capture commit Git, dépôt, ref, pipeline CI déclenchant et horodatages ; artefacts locaux liés à leur **SHA-256**.
- **Quatre modes de signature** : JSON non signé, clé PEM locale, KMS cloud ou Vault, et **Sigstore Fulcio** sans clé avec publication Rekor.
- **Mapping direct sur l'échelle SLSA** L1 / L2 / L3, avec workflows GitHub Actions de référence.
- **Entièrement opt-in** : les templates existants construisent sans modification sous 1.16.0.
