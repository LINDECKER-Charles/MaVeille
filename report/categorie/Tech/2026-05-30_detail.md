# Tech — Détail du samedi 30 mai 2026

## 1. NGINX Rift (CVE-2026-42945) — heap overflow vieux de 18 ans, exploité

**Source :** Help Net Security — https://www.helpnetsecurity.com/2026/05/18/ngnix-vulnerability-exploited-cve-2026-42945/
**Date :** 13 mai 2026 (exploitation active confirmée le 18 mai)

### Contexte

Une faille **heap-based buffer overflow** dans le module `ngx_http_rewrite_module` de nginx, surnommée **NGINX Rift**, dort dans le code depuis ~18 ans. Elle touche le serveur web le plus déployé d'Internet, et elle est désormais **activement exploitée**.

### Ce qui change concrètement

- CVSS **9.2 (Critique)**. Affecte **nginx Open Source 0.6.27 → 1.30.0** et **nginx Plus R32 → R36**.
- Déclenchement : une directive `rewrite` qui utilise une capture PCRE non nommée (`$1`, `$2`) avec un remplacement contenant un `?`, suivie d'une autre directive `rewrite`/`if`/`set`.
- nginx calcule la taille du buffer avec une méthode d'échappement et écrit avec une autre. Les caractères `+`, `%`, `&` se ré-échappent et l'écriture déborde de l'allocation.
- Une seule requête HTTP forgée suffit : DoS du worker, voire **RCE non authentifiée** si l'ASLR est désactivé.

### Pourquoi ça compte pour toi

Si tu as un nginx en frontal de tes apps .NET/Symfony, patche en priorité absolue. Audite tes blocs `rewrite` utilisant `$1`/`$2` avec un `?` dans le remplacement — c'est le pattern déclencheur. La 1.30.1 / nginx Plus R36 P1 corrigent ; à défaut de patch immédiat, désactive temporairement les rewrites concernées.

### Points de vigilance

- Le WAF en amont ne te protège pas forcément : le payload tient dans une requête HTTP valide.

## 2. Apache HTTP/2 (CVE-2026-23918) — double-free dans mod_http2

**Source :** The Hacker News — https://thehackernews.com/2026/05/critical-apache-http2-flaw-cve-2026.html
**Date :** mai 2026

### Contexte

Faille de type **double-free with possible RCE** dans la gestion du protocole HTTP/2 d'Apache httpd, dans le chemin de nettoyage de stream de `h2_mplx.c`.

### Ce qui change concrètement

- CVSS **8.8**. Affecte **Apache HTTP Server 2.4.66**, corrigé en **2.4.67**.
- Déclenchement : le client envoie une frame HTTP/2 `HEADERS` immédiatement suivie d'un `RST_STREAM` avec un code d'erreur non nul sur le même stream, **avant que le multiplexer n'ait enregistré le stream**.
- Le double-free ouvre la voie à un crash et potentiellement une exécution de code.

### Pourquoi ça compte pour toi

Si tu sers du HTTP/2 derrière Apache, monte en **2.4.67** sans attendre. Si tu ne peux pas patcher tout de suite, désactiver temporairement `mod_http2` (retour HTTP/1.1) supprime la surface d'attaque au prix d'un peu de perf. Vérifie aussi tes reverse-proxies et images Docker basées sur httpd.

### Limites

- L'exploitation en RCE fiable reste non triviale ; le risque immédiat est surtout le DoS.

## 3. Symfony 8.1 + avalanche d'advisories Symfony UX

**Source :** Symfony Blog — https://symfony.com/blog/
**Date :** 29 mai 2026

### Contexte

Symfony a publié les **nouveautés curées de la 8.1** et, le même jour, **plusieurs advisories de sécurité** visant des composants **Symfony UX**.

### Ce qui change concrètement

- Annonce des nouvelles fonctionnalités **Symfony 8.1** (cycle de release standard).
- Plusieurs advisories Symfony UX le **29 mai** : **déni de service**, **XSS**, et **contournements de protection CSRF** dans divers composants UX.

### Pourquoi ça compte pour toi

Tu fais du Symfony : vérifie immédiatement quelles versions de composants `symfony/ux-*` tu utilises (`composer outdated 'symfony/*'`) et applique les correctifs. Les bypass CSRF et XSS sont directement exploitables côté front. Ne te contente pas de bumper Symfony : les advisories ciblent les paquets UX, souvent versionnés séparément.

### Points de vigilance

- Vérifie tes templates Twig qui rendent du contenu UX : un XSS UX peut transiter par des données que tu croyais sûres.

## 4. Patch Tuesday mai — Azure DevOps (CVSS 10) et Dynamics 365 RCE

**Source :** CrowdStrike — https://www.crowdstrike.com/en-us/blog/patch-tuesday-analysis-may-2026/
**Date :** 12 mai 2026

### Contexte

Le Patch Tuesday de mai a corrigé 132 CVE. Deux se détachent pour un dev backend de l'écosystème Microsoft.

### Ce qui change concrètement

- **CVE-2026-42826** (Azure DevOps) : divulgation d'information, **CVSS 10**. Un attaquant non authentifié peut récupérer des informations sensibles à distance, sans interaction.
- **CVE-2026-42898** (Dynamics 365 on-premises) : **RCE critique CVSS 9.9**. Injection de code exploitable par tout attaquant authentifié à distance, sans interaction utilisateur.

### Pourquoi ça compte pour toi

Si ta CI/CD passe par Azure DevOps, la CVE-2026-42826 expose potentiellement secrets et code source : applique la mise à jour serveur et fais tourner tes secrets par précaution. Pour Dynamics 365 on-prem, patche et restreins l'accès réseau. Les instances cloud managées sont corrigées côté Microsoft.

### Points de vigilance

- Un CVSS 10 « information disclosure » non authentifié mérite une rotation de tokens, pas seulement un patch.
