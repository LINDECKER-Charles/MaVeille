# Tech — Détail du vendredi 5 juin 2026

## 1. VS Code github.dev zero-day — vol de tokens GitHub OAuth en un seul clic

**Source :** Bleeping Computer — https://www.bleepingcomputer.com/news/security/vs-code-zero-day-lets-hackers-steal-github-tokens-in-one-click/
**Date :** 4 juin 2026

### Contexte

Le chercheur Ammar Askar a divulgué le 2 juin une vulnérabilité dans le mécanisme de passage de messages entre la fenêtre principale de VS Code et ses webviews, tel qu'utilisé par `github.dev`. La divulgation a été publiée une heure seulement après la notification à GitHub — contournant la fenêtre de responsible disclosure standard, suite à une perte de confiance déclarée dans le processus Microsoft. Microsoft a néanmoins livré un correctif d'urgence côté service le 3 juin.

### Ce qui change concrètement

- Le vecteur exploite les **messages postMessage entre webview et fenêtre principale** de VS Code.
- Sur `github.dev` (navigateur) : en cliquant sur un lien piégé, un script malveillant simule des frappes clavier (`Ctrl+Shift+P`), ouvre la palette de commandes, installe une extension contrôlée par l'attaquant, puis **exfiltre le token GitHub OAuth**.
- Avec ce token : accès en lecture et écriture sur **tous les dépôts privés** accessibles à la victime.
- Sur VS Code Desktop : vecteur similaire mais plus difficile à exploiter — nécessite de cloner un repo et d'ouvrir un notebook contenant le payload webview.
- **Correctif Microsoft** : mitigé côté services GitHub (github.dev) le 3 juin, aucune action utilisateur requise pour ce vecteur. VS Code Desktop en attente d'un patch complet.

### Pourquoi ça compte pour toi

Si tu travailles sur `github.dev` (prévisualisation de PR, édition légère dans le navigateur) et que tu as cliqué sur des liens non vérifiés récemment, **inspecte tes sessions GitHub actives** (Settings → Sessions) et révoque les tokens suspects. En CI/CD, assure-toi que les tokens d'accès ont une portée minimale (`contents:read` au lieu de `repo` complet). Ne jamais ouvrir de notebooks Jupyter provenant de dépôts non fiables dans VS Code Desktop.

### Points de vigilance

- Le correctif couvre `github.dev` (service web). Le vecteur VS Code Desktop reste partiellement exposé — limite l'ouverture de notebooks depuis des repos inconnus.
- La divulgation anticipée a rendu le vecteur public avant couverture complète : surveille les mises à jour de VS Code dans les prochains jours.

## 2. Android juin 2026 : Google patche 124 failles, CVE-2025-48595 activement exploitée

**Source :** The Hacker News — https://thehackernews.com/2026/06/google-june-2026-android-update-patches.html
**Date :** 2 juin 2026

### Contexte

Google a publié le Patch Tuesday Android de juin 2026, couvrant 124 CVEs. Une faille — CVE-2025-48595 — est confirmée activement exploitée et a été ajoutée au catalogue CISA KEV avec une deadline de remédiation fixée au 5 juin 2026 pour les agences fédérales américaines. Le bulletin est parmi les plus volumineux de l'année.

### Ce qui change concrètement

- **CVE-2025-48595** (CVSS 8.4, composant Framework Android) : escalade de privilèges **sans interaction utilisateur requise**. Une app malveillante peut élever ses droits silencieusement.
- **CVE-2025-65018** : vulnérabilité Framework critique permettant une élévation de privilèges distante sans interaction — le correctif le plus sévère du bulletin.
- Le patch couvre les composantes Framework, System, Media, et les composants fabricants (Qualcomm, MediaTek).
- Mise à jour OTA disponible depuis le 2 juin sur les appareils Pixel ; délai variable (4-8 semaines) pour les autres fabricants.

### Pourquoi ça compte pour toi

Si tu gères une flotte Android en entreprise (MDM, BYOD), priorise la mise à jour sur les appareils accédant aux ressources internes. CVE-2025-48595 sans interaction signifie qu'une app latente peut élever ses droits sans déclencher d'alerte utilisateur — vecteur discret et particulièrement dangereux en contexte BYOD. Pour les apps publiées sur Android via Capacitor ou MAUI, vérifie que tes bibliothèques WebView sont à jour et que le minSdkVersion cible une version patchée.

### Détails techniques

- Niveaux de patch concernés : 2026-06-01 et 2026-06-05.
- Android 13, 14 et 15 bénéficient tous du correctif selon le niveau de patch appliqué.
- Pour les flottes BYOD sans MDM : communique le bulletin aux utilisateurs et fixe une deadline interne cohérente avec la politique de sécurité.
