# Angular — Détail du vendredi 5 juin 2026

## 1. MCP + Angular v22 : l'IA transforme le workflow dev au-delà du scaffolding

**Source :** Angular Blog (newsletter officielle) — https://blog.angular.dev/angular-in-2026-mid-year-reality-check-signals-and-ai-code-quality-ff37df480574
**Date :** 5 juin 2026

### Contexte

La newsletter hebdomadaire du 5 juin tombe le lendemain de la GA Angular v22 et fait le bilan de mi-2026. Le sujet le plus concret pour un dev senior est l'article de Sonu Kapoor publié sur CodeMag — [From Commands to Conversations: How AI-Assisted Tooling Is Transforming Angular Development](https://www.codemag.com/Article/2601071/From-Commands-to-Conversations-How-AI-Assisted-Tooling-Is-Transforming-Angular-Development) — qui documente la transition d'un outillage CLI passif vers un cycle agentique actif, catalysé par le Model Context Protocol passé stable dans Angular v22.

### Ce qui change concrètement

- L'**Angular MCP server** (stable en v22) expose des outils opérationnels : `devserver.wait_for_build`, `devserver.start`, `devserver.stop`, AI tutor, `onpush_zoneless_migration`, `modernize`.
- Les agents peuvent désormais **lancer le dev server, observer les erreurs de build et itérer** en boucle auto-correctrice, sans intervention manuelle.
- Le MCP connaît les API modernes (Signals, Signal Forms, Angular Aria, `httpResource`, `injectAsync`, `@Service()`) là où un LLM entraîné avant fin 2025 les ignorait.
- Les **Angular Agent Skills** (`github.com/angular/skills`) permettent d'injecter du contexte v22 dans n'importe quel agent, même sans MCP configuré.
- **WebMCP expérimental** : Angular v22 introduit le support de WebMCP (Chrome), permettant d'exposer des outils d'application directement aux agents IA dans le navigateur.

### Pourquoi ça compte pour toi

Si tu utilises Cursor, Claude Code ou Antigravity avec Angular, configure le MCP server plutôt que de te fier aux complétions brutes du modèle. Tu éviteras les générations de code obsolète et tu bénéficieras des boucles de feedback sur le build. L'outil `onpush_zoneless_migration` est le point d'entrée le plus direct pour préparer un projet v21 à fonctionner sans Zone.js en v22.

### Points de vigilance

- Le MCP server Angular nécessite Angular CLI v22 — vérifie la version globale avant de l'activer dans ton IDE.
- Les outils `devserver.*` ne sont stables qu'en v22 — sur un projet v21 en cours de migration, reste sur les outils expérimentaux documentés sur `angular.dev/ai/mcp`.

## 2. "Ton IA code Angular comme en 2022" — LLMs obsolètes, zoneless readiness et correctifs pratiques

**Source :** Angular Blog (newsletter officielle) — https://blog.angular.dev/angular-in-2026-mid-year-reality-check-signals-and-ai-code-quality-ff37df480574
**Date :** 5 juin 2026

### Contexte

Muhammad Ahsan Ayaz publie deux vidéos référencées dans la newsletter : un récapitulatif d'Angular v21 et une analyse directe sur [pourquoi les assistants IA génèrent encore du code Angular obsolète](https://youtu.be/tCROVJMcAF8). Alain Chautard complète avec une checklist pratique — [Is Your Angular App Ready for Zoneless?](https://www.youtube.com/watch?v=mcSR6IIKvEE) — pour évaluer la maturité zoneless d'un projet avant de lancer la migration v22. Ces deux ressources forment le guide actionnable de mi-2026.

### Ce qui change concrètement

Les LLMs entraînés avant fin 2025 génèrent systématiquement des patterns devenus obsolètes ou renommés en v22 :

- `NgModule` à la place des standalone components (défaut depuis v17, encore omniprésent dans les suggestions IA)
- `ChangeDetectionStrategy.Default` au lieu de `ChangeDetectionStrategy.Eager` (renommé en v22)
- `@Injectable({ providedIn: 'root' })` au lieu de `@Service()` (nouveau décorateur v22)
- Imports `zone.js` dans `polyfills.ts` sur des projets ciblant le zoneless
- Syntax de formulaire `FormControl` / `FormGroup` reactive au lieu de Signal Forms

**Correctifs immédiats :**

1. Prompt système explicite : `"Use Angular 22 conventions: @Service() for root services, OnPush by default, no Zone.js imports, Signal Forms API from @angular/forms/signals."`
2. Configurer le MCP server Angular (voir sujet 1) qui injecte automatiquement les conventions v22.
3. Activer les Angular Agent Skills dans ton environnement d'agent.

**Checklist zoneless (Alain Chautard) — points principaux :**

- Détecter les appels directs à `NgZone` dans le code applicatif
- Remplacer les `ChangeDetectorRef.markForCheck()` par des mutations de signal
- Auditer les timers et event handlers déclenchés hors du contexte Angular
- Vérifier que les bibliothèques tierces supportent le mode zoneless (Angular Material v22 : OK)

### Pourquoi ça compte pour toi

Chaque composant généré via IA sans contexte v22 risque d'introduire `ChangeDetectionStrategy.Eager` implicitement ou des imports Zone.js qui cassent les bénéfices de la migration. Trente secondes à configurer un prompt système ou le MCP server évitent des heures de refactoring post-review. La checklist zoneless est particulièrement utile avant de planifier un sprint de migration : elle donne une estimation réaliste du périmètre.

### Points de vigilance

- La migration zoneless n'est pas atomique : Zone.js peut rester dans des dépendances tierces (bibliothèques pré-v22 non encore mises à jour).
- Les tests avec `TestBed` + zoneless change detection nécessitent une mise à jour des fixtures — `detectChanges()` reste nécessaire mais se comporte différemment (synchrone dans le nouveau mode).
- Le `@boundary` template (error boundaries) est en developer preview pour Q3 2026 — à ne pas utiliser en prod encore.
