# Angular — Synthèse du dimanche 30 août 2026

## Digest court

Journée sans release Angular, mais l'écosystème front bouge sur deux fronts très différents. **htmx 4.0.0** est sorti le 28 août après huit mois de travail : les internals passent de `XMLHttpRequest` à `fetch()`, l'héritage d'attributs devient **explicite**, les événements sont renommés en `htmx:phase:action`, et l'historique abandonne `localStorage`. Trois changements de comportement qui touchent toute base de code htmx 2. En parallèle, un développeur a découvert que les pages AliExpress ouvrent **deux `AudioContext` silencieux** au chargement — un fingerprint matériel via la Web Audio API qui, au passage, casse le Bluetooth multipoint. Les deux sujets rappellent la même chose : une API navigateur inoffensive en apparence peut porter des effets de bord bien réels.

## Top 1 — htmx 4.0.0 : trois changements de comportement à absorber

- **Héritage explicite** : `hx-confirm` sur un parent ne descend plus aux enfants sans le suffixe `:inherited`. C'est le gros morceau de migration.
- **Événements normalisés** : `htmx:afterRequest` devient `htmx:after:request`, les `htmx:xhr:*` et `htmx:validation:*` disparaissent.
- **Historique sans `localStorage`** : le retour arrière refait une requête réseau au lieu de restaurer un snapshot DOM pollué par des libs tierces.
- **Nouveautés** : morph swaps intégrés (idiomorph amélioré) et balise `<hx-partial>` pour cibler plusieurs zones dans une même réponse.
- **Outillage** : `npx htmx.org@4.0.0 upgrade-check -- ./templates` liste les attributs à corriger, fichier par fichier et ligne par ligne.

htmx 2 reste taggé `latest` sur npm jusqu'à début 2027 — aucune mise à jour forcée si tu pointes une URL CDN non versionnée.

## Top 2 — Fingerprinting audio : la Web Audio API sans garde-fou

- **Deux `AudioContext` en état `running`** créés par `collina.js` et `fireyejs.js` (répertoire AWSC d'Alibaba) sur la homepage AliExpress.
- **Graphe silencieux** : oscillateur → `AnalyserNode` → `ScriptProcessorNode` → `GainNode` à 0 → `destination`. Inaudible, mais actif.
- **Signature matérielle** : les micro-écarts de calcul flottant (FMA, NEON, pilotes audio) rendent la sortie fréquentielle discriminante, puis hachée en identifiant stable.
- **Effet de bord** : le flux audio ouvert au niveau plateforme verrouille le routage Bluetooth multipoint — couper le son de l'onglet n'y change rien.
- **Défenses** : Brave injecte du bruit (« farbling ») ; Firefox rend la sortie quasi constante depuis la 118 (trois valeurs pour 99,24 % des utilisateurs).

Le point de spec : créer un `AudioContext` ne demande **aucune permission** et n'affiche **aucun indicateur** quand l'amplitude est nulle, contrairement à `getUserMedia` ou à la Geolocation API.
