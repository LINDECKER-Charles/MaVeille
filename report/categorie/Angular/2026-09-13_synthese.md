# Angular — Synthèse du dimanche 13 septembre 2026

## Digest court

Dimanche calme côté framework : rien de neuf sur le blog Angular ni sur la ligne `22.2.0-next`. L'actualité front de ce week-end se joue sur la **chaîne d'outils**. `tsgolint`, le moteur de lint type-aware d'**Oxlint**, est passé **stable en v7** le 11 septembre. Il ne réimplémente pas de type checker : il construit de vrais programmes TypeScript au-dessus de **typescript-go**, le portage Go officiel du compilateur qui devient TypeScript 7. Résultat annoncé : **12 à 18× plus rapide** qu'ESLint + typescript-eslint, avec **59 des 61 règles** type-aware couvertes. Le prix d'entrée est net : il faut TypeScript 7.0 ou plus.

## Top 1 — tsgolint v7 : le lint type-aware quitte le monde JavaScript

- **Architecture à deux étages** : Oxlint (Rust) gère config, découverte de fichiers et règles syntaxiques ; il délègue le type-aware à un binaire Go.
- **`pnpm add -D oxlint oxlint-tsgolint@7` puis `oxlint --type-aware`** : deux commandes pour démarrer.
- **59/61 règles** typescript-eslint couvertes, contre 43 à l'alpha de décembre.
- **Versionnage aligné sur le compilateur** : `v7.0.2000` correspond à TypeScript **7.0.2**. Le saut direct du 0.x au v7 est volontaire.
- **Migration assistée** : `npx @oxlint/migrate --type-aware` traduit une config ESLint existante.
- **Contrainte dure** : TypeScript **7.0+** requis, `baseUrl` et quelques options tsconfig héritées ne sont pas supportées.

À noter, côté honnêteté : l'équipe typescript-eslint qualifie encore son propre fork de tsgolint d'expérience « pas en développement actif », et des rapports de correctness circulent côté oxc — dont un autofix qui supprimait une assertion de type que `tsc` exigeait.
