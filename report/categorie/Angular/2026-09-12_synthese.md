# Angular — Synthèse du samedi 12 septembre 2026

## Digest court

Journée calme côté framework : `angular/angular` n'a rien publié depuis le 9 septembre, et sa dernière préversion annonce explicitement « no user facing changes ». Tout le mouvement est dans la **chaîne d'outils**. Le 10 septembre, Vite sort **8.3.0 stable** et supprime son `esbuildPlugin` devenu inutile — la bascule vers Rolldown et oxc est désormais actée dans le code, plus seulement dans la roadmap. Le même jour, l'équipe Angular CLI publie quatre releases d'un coup, dont **22.1.8 stable** et **22.2.0-next.7**, avec un lot de perf entièrement concentré sur le cache disque SQLite et le watch. Elle **déprécie l'option `splitting`** du builder `unit-test`, devenue superflue avec Vitest 5. Aucune publication technique vérifiable le 11 ni le 12 dans le périmètre front.

## Top 1 — Vite 8.3.0 : les hooks de fermeture serveur, et la sortie d'esbuild

- **`closeServer` et `closePreviewServer`** : deux nouveaux hooks de cycle de vie pour libérer les ressources d'un plugin custom (PR #23110).
- **Option top-level `tsconfig`** : plus besoin d'un plugin pour pointer un `tsconfig` alternatif (PR #23310).
- **`esbuildPlugin` supprimé** du code (PR #23381) — esbuild quitte le chemin de build au profit de Rolldown/oxc.
- **Fix de classement `node_modules`** : seuls les segments de chemin entiers comptent désormais comme dépendance (issue #17467).
- **`server.watch`** accepte les options de watch Rolldown (PR #23133).

## Top 2 — Angular CLI 22.1.8 / 22.2.0-next.7 : `splitting` déprécié, cache SQLite durci

- **`splitting` déprécié** dans le builder `unit-test` : le bug JSDOM sur les champs de classe est corrigé en amont par Vitest 5.
- **Cache SQLite** : récupération automatique de corruption, création du répertoire parent, compression sélective des grosses entrées.
- **Read-locks SQLite éliminés** : les métadonnées de cache sont vérifiées avant toute lecture de fichier.
- **Type-checking diagnostique découplé du démarrage du build** — le build ne l'attend plus.
- **`preloadInitial` passe à `false` par défaut** quand le service worker est activé : le HTML généré change.

Le 9 septembre avait concentré les vraies nouveautés de framework (ErrorBoundary programmatique, blocs `@boundary` côté language service, ressources du router en API publique). Ces sujets tombent hors de la fenêtre de 48 h et ne sont pas traités ici.
