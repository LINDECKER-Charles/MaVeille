# Angular — Synthèse du dimanche 20 septembre 2026

## Digest court

Journée calme côté écosystème front, mais une pièce majeure se met en place pour Angular 22.2 : les **error boundaries de template**, `@boundary` / `@error`, dont la documentation officielle vient d'être fusionnée dans `angular/angular` et dont la 22.2.0-rc.0 est sortie le 16 septembre. C'est la première fois qu'Angular propose une isolation d'erreur au niveau du **compilateur de template**, sans composant wrapper ni `ErrorHandler` global détourné. La primitive s'accompagne d'un `onError` sur `createComponent` pour les vues créées impérativement. L'écosystème outillage suit déjà : Prettier a une PR ouverte pour formater les nouveaux blocs. Rien d'autre de significatif sur les flux Angular et TypeScript en 48 h — on privilégie la profondeur.

## Top 1 — `@boundary` / `@error` : l'isolation d'erreur descend dans le template

- **`@boundary { … } @error (let err) { … }`** : un sous-arbre qui plante n'emporte plus la page, le bloc `@error` prend le relais avec l'erreur en variable
- **`$reset`** : la primitive de relance exposée dans le bloc `@error` (renommée depuis `$retry` pendant la revue du compilateur)
- **`createComponent(Dynamic, { onError })`** : même sémantique pour les vues créées via `ViewContainerRef` ou l'API standalone
- **Statut** : developer preview, cible `target: minor` 22.2 — docs fusionnées le 10 septembre, RC depuis le 16
- **Outillage** : PR Prettier #20015 ouverte pour le formatage des blocs `@boundary`

Concrètement, tu passes d'un `ErrorHandler` global qui constate les dégâts après coup à une frontière déclarative qui décide, widget par widget, ce que l'utilisateur voit à la place.
