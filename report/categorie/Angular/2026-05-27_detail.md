# Angular — Détail du mercredi 27 mai 2026

## 1. Angular 22 RC1 — Signal Forms, zoneless par défaut

**Source :** Angular Release Guide — https://angular.dev/reference/releases
**Date :** 22 mai 2026 (RC1)

### Contexte

Angular pousse depuis la version 16 (mai 2023) son modèle de réactivité basé sur les **signaux**, en alternative à RxJS et au mécanisme historique de change detection basé sur Zone.js. Les versions 17 à 21 ont progressivement migré l'écosystème : Computed Signals, Signal Inputs, Signal Queries, puis l'API expérimentale Signal Forms en v21. La v22 marque l'aboutissement : **Signals devient stable, zoneless devient le défaut pour les nouveaux composants, et Signal Forms passe en production-ready**. C'est la fin officielle de l'ère « Angular avec Zone.js », même si la rétrocompatibilité est maintenue pour permettre des migrations progressives.

### Ce qui change concrètement

**Signals API stable** — Plus d'API expérimentales sur les signaux : `signal()`, `computed()`, `effect()`, ainsi que les Signal Inputs (`input.required<T>()`) et Signal Queries (`viewChild()`, `contentChild()`) deviennent stables. Tu peux les utiliser en prod sans risque de breaking changes.

**Signal Forms** — Remplacent Reactive Forms. Le state du formulaire est désormais un `signal`, ce qui élimine les `Subscription`, les `FormControl.valueChanges` à pipe, et les recalculs manuels. Le typage est inféré du modèle : finis les `get('email')?.value` potentiellement `any`.

**Zoneless par défaut** — Les nouveaux composants utilisent OnPush + signal-based reactivity sans Zone.js. Réduction substantielle de la taille du bundle (suppression de zone.js ≈ 30 Ko gzipped) et meilleur tree-shaking. Les composants existants continuent de fonctionner avec Zone.js.

**Selectorless Components** — Tu peux importer un composant directement dans un template sans définir de selector string : `import { UserCard } from './user-card';` puis `<UserCard [user]="..."/>`. Simplifie la composition et améliore l'ergonomie IDE.

### Pourquoi ça compte pour toi

Si tu maintiens des apps Angular en prod, c'est **la migration la plus structurante depuis l'introduction de Standalone Components**. Tu peux y aller en deux temps : d'abord migrer vers la v22 en mode compatibilité Zone.js (pas de breaking change critique), puis migrer progressivement composant par composant vers signals + zoneless. Les Signal Forms vont demander une réécriture de tes formulaires complexes — prévois du temps. Bénéfice principal : meilleure performance, moins de boilerplate, code plus simple à raisonner.

### Points de vigilance

**Compatibilité des libs tierces** — Toutes les libs Angular ne sont pas zoneless-ready. Angular Material est OK depuis la v18, mais des libs plus petites (datepickers custom, charts wrappers, etc.) peuvent encore dépendre implicitement de Zone.js pour leurs détections de changement. Audit recommandé avant de désactiver Zone.js globalement.

**RxJS reste pertinent** — Signals ne remplacent pas RxJS pour les flux async complexes (websockets, retry/debounce, combineLatest sur 5 sources). Les deux coexistent : signals pour le state UI, RxJS pour les flux. Les helpers `toSignal()` et `toObservable()` font le pont.

**Date de release stable** — RC1 sorti le 20 mai, stable attendue fin mai / début juin 2026.
