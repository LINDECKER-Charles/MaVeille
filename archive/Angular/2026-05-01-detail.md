## 1. TypeScript

### 1.1 TypeScript 7.0 Beta — annonce officielle (21 avril 2026)

Microsoft a publié la **première bêta publique de TypeScript 7.0** le 21 avril 2026. C'est l'aboutissement du *Project Corsa*, le portage du compilateur TypeScript depuis JavaScript/TypeScript vers **Go**. Le code n'a pas été réécrit *from scratch* : il a été porté méthodiquement, ce qui garantit que la logique de typage est **structurellement identique** à celle de TypeScript 6.0.

**Performances annoncées et mesurées :**

- Sur le repo TypeScript lui-même (~400k lignes) : compilation **10,8× plus rapide**, vérification de types **30× plus rapide**, mémoire **2,9× moindre**.
- Sur le repo de VS Code (~400k lignes TypeScript) : passage de **89 s à 8,74 s** (×10,2).
- Sur Sentry : passage de **133 s à 16 s**, démarrage de l'éditeur de **9,6 s à 1,2 s**, mémoire grosso modo divisée par deux.

**Installation et usage :**

```bash
npm install -D @typescript/native-preview@beta
```

Le binaire s'appelle **`tsgo`** (au lieu de `tsc`). Microsoft insiste sur la coexistence : `tsgo` peut être utilisé en parallèle de `tsc` 6.0 pour faciliter la comparaison et la validation côté équipes.

**Support éditeur :**

Le serveur de langage est désormais bâti sur le **Language Server Protocol (LSP)**, ce qui doit améliorer l'intégration dans des éditeurs autres que VS Code (Neovim, JetBrains, Helix, etc.). Microsoft décrit la qualité du support comme « rock-solid ».

**Adoption en avant-première :**

La bêta a été testée chez Bloomberg, Canva, Figma, Google, Lattice, Linear, Miro, Notion, Slack, Vanta, Vercel et VoidZero. Les retours sont qualifiés de très positifs et la plupart des équipes constatent des temps de build au moins divisés par deux.

**Pourquoi Go et pas Rust ?**

Selon Microsoft, le choix de Go est lié à un **alignement architectural** plus naturel avec le code TypeScript existant (modèle de mémoire, concurrence, garbage collection), permettant un *portage* plutôt qu'une *réécriture*. La trajectoire envisageable en Rust aurait été pluri-annuelle.

### 1.2 Contexte : sortie de TypeScript 6.0 (mars 2026)

Pour mémoire, **TypeScript 6.0** a été publié en mars 2026 comme **dernière version JavaScript-based** de la lignée. Il sert de socle de référence comportementale pour 7.0 et reçoit encore des mises à jour pendant la phase de transition.

## 2. Angular

### 2.1 Version supportée actuelle : Angular 21.2.10 (22 avril 2026)

La dernière version supportée à ce jour est **Angular 21.2.10**, publiée le 22 avril 2026. Le support actif court jusqu'au **19 mai 2027**.

**Cycle de support en cours :**

| Version | Statut | Fin de support |
| --- | --- | --- |

| Angular 19 | Fin de vie imminente | **19 mai 2026** |

> Action recommandée : si vos projets sont encore en Angular 19, **planifiez la migration sous 3 semaines**.

### 2.2 Rappel — apports majeurs d'Angular 21 (toujours d'actualité)

- **Signal Forms (expérimentales)** : nouvelle API de formulaires construite sur les Signals, qui combine la légèreté des template-driven forms et la puissance des reactive forms.
- **Vitest comme test runner par défaut** : remplace Karma/Jasmine pour les nouveaux projets (Karma reste supporté). Apporte fake timers, snapshots, parallélisation native.
- **Zoneless par défaut** : Zone.js n'est plus inclus dans les nouveaux projets ; la détection de changement « zone-less » devient le mode standard.
- **`@angular/aria`** : nouveau package fournissant les briques d'accessibilité pour les bibliothèques de composants.
- **MCP Server intégré au CLI** : outils d'aide au développement assistés par IA.

### 2.3 Angular 22 — sortie attendue en mai 2026

Angular 22 est prévu autour de **mai 2026**. Les builds pré-release `22.0.0-next` sont disponibles depuis avril 2026. Fonctionnalités attendues :

- **Selectorless components** : import direct des composants dans les templates, sans avoir à déclarer / mémoriser un sélecteur. Pensé pour améliorer la *refactorability* et simplifier la consommation.
- **Signal Forms stables** : sortie de l'expérimental.
- **OnPush par défaut** sur les nouveaux composants.
- **Support de TypeScript 5.9**.
- **Nouvelles primitives Signals** : `debounced()`, `resource()` — élargit la surface réactive pour rester dans le graphe de signaux.
- **Investissement continu** sur l'Angular MCP Server et l'outillage AI-assisted introduit en v21.

### 2.4 Sécurité — patches SSR (rappel février 2026)

Pour mémoire, deux CVE Angular SSR ont été corrigées le **27 février 2026** : SSRF + Header Injection, et Open Redirect via `X-Forwarded-Prefix`. Si la mise à jour SSR n'a pas été passée, c'est à prioriser.
