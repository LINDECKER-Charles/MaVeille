## 1. TypeScript

### 1.1 TypeScript 7.0 Beta — Project Corsa

Microsoft a officialisé le **21 avril 2026** la disponibilité publique de **TypeScript 7.0 Beta**, point d'orgue du chantier interne baptisé *Project Corsa*. Cette version marque la première mouture publique du compilateur réécrit intégralement en **Go**, à la place de l'implémentation TypeScript-sur-Node historique.

**Comment l'essayer :**

```bash
npm install --save-dev @typescript/native-preview@beta
npx tsgo --version
```

Le binaire `tsgo` peut être exécuté en parallèle de `tsc` pour comparer les sorties (mêmes diagnostics, même sémantique de typage attendue).

### 1.2 Architecture et performances

La bascule en Go apporte trois leviers de performance :

- **Code natif compilé** : suppression de la couche d'interprétation V8/Node.js entre le compilateur et l'OS.
- **Mémoire partagée et parallélisation** : parsing, type-checking et émission peuvent désormais s'exécuter concurremment sur plusieurs fichiers.
- **Builds multi-projets** : le nouveau drapeau `--builders` permet de bâtir plusieurs projets simultanément, ce qui change la donne pour les monorepos.

Microsoft annonce un facteur **×10 sur les très gros codebases**. Les retours indépendants (benchmarks publiés sur Medium par des contributeurs externes) confirment plutôt **×2 à ×5 sur des projets <100k lignes** et des facteurs supérieurs sur les très grosses bases.

### 1.3 Intégration éditeur

L'extension VS Code « TypeScript Native Preview » a vu arriver en avril :

- auto-imports
- expandable hovers
- inlay hints
- code lenses
- go-to-source-definition
- JSX linked editing et tag completions

Une mise à jour récente du même mois supprime également les complétions Copilot pendant qu'IntelliSense est actif, mettant fin à un conflit de longue date dans l'éditeur. VS Code 1.117 introduit de plus le support **bring-your-own model key** pour Copilot Business/Enterprise.

### 1.4 Adoption en production

La beta est annoncée comme « production-ready » pour de nombreux flows quotidiens et pipelines CI. Liste publique des organisations ayant déjà testé ou intégré la beta :

Bloomberg, Canva, Figma, Google, Lattice, Linear, Miro, Notion, Slack, Vanta, Vercel, VoidZero.

### 1.5 Stratégie de migration

La migration officielle se découpe en deux phases :

**Phase 1 — TypeScript 6.0** (sortie le 23 mars 2026) : dernière version de la base JavaScript historique. Sert de jalon de transition (dépréciations, changements de valeurs par défaut, drapeau de migration).

**Phase 2 — TypeScript 7.0** (stable attendu mi à fin 2026) : remplacer `tsc` par `tsgo` dans les scripts de build. Pour la plupart des projets, ce sera une simple bump de version.

Étapes recommandées :

- activer `strict` si ce n'est pas déjà fait et corriger les erreurs (`tsc --strict`)
- s'éloigner de `baseUrl` pour la résolution de modules (préférer `paths` explicites ou changer `moduleResolution`)
- installer `@typescript/native-preview` et exécuter `tsgo` en parallèle de `tsc` pour confronter les diagnostics

### 1.6 À surveiller

- date du **TS 7.0 stable** (fenêtre annoncée mi-fin 2026)
- compatibilité des outils tiers (ts-node, ts-jest, ts-loader, esbuild, swc) avec `tsgo`
- évolution des règles de typage spécifiques à Go (perf vs sémantique)

## 2. Angular

### 2.1 Version courante et calendrier de support

| Version | Statut | Fin de support active |
|---------|--------|----------------------|
| **Angular 21.2.10** | Active (LTS courante) | 19 mai 2027 |
| Angular 20.x | Supportée | 28 novembre 2026 |
| Angular 19.x | Fin de support proche | **19 mai 2026** |

Angular 21 est sorti le 19 novembre 2025. Le rythme semestriel est tenu, Angular 22 est attendu pour fin 2026.

### 2.2 Zoneless par défaut

Depuis Angular 21, le **mode Zoneless est le défaut sur les nouvelles applications** créées via la CLI. C'est la suite logique du virage signal-first amorcé en v17/v18.

Bénéfices observés :

- **20 à 30 % de gains runtime** dans des applications réelles
- **−400 ms TTI mobile** sur Gmail après migration interne Google
- détection de changements déterministe et minimale (un signal change → seuls les nœuds dépendants sont re-rendus)

Migration : `provideExperimentalZonelessChangeDetection()` côté bootstrap, vérification des dépendances qui requièrent encore `zone.js` (RxJS, certains polyfills, packages tiers anciens).

### 2.3 Signal Forms

Les **Signal Forms** sont entrés en preview avec Angular 21 et continuent d'évoluer en avril 2026. Nouvelles primitives :

- `debounced()` — debounce intégré au graphe de signaux (utile pour les recherches)
- `resource()` — chargement asynchrone réactif (champs dépendants, données paresseuses)
- `reloadValidation`, `FieldState.getError()`, instanciation paresseuse de champs (pre-releases v22)

Avantages annoncés :

- mises à jour **fine-grained** : changer un champ dans un formulaire de 50 champs ne re-rend que ce champ
- modèle réactif unifié sans dépendance forte à RxJS
- meilleure interopérabilité avec les Reactive Forms existants pour migrer progressivement

Stabilisation prévue en **Angular 22**.

### 2.4 Angular CLI et Model Context Protocol

Angular 21 inclut un premier vrai « hook IA » dans la CLI via le **Model Context Protocol (MCP)**. Concrètement, la CLI peut exposer du contexte projet (structure, règles, dépendances) à un agent LLM compatible MCP pour produire du code, des migrations ou des refactorings plus pertinents.

C'est une étape vers une expérience CLI augmentée par l'IA et un signal fort sur la direction prise par l'écosystème.

### 2.5 Roadmap Angular 22

Les éléments en pré-release ou roadmap pour la prochaine version majeure (fin 2026) :

- **Signal Forms stables**
- **Selectorless components** (utilisation de composants sans selector explicite)
- **OnPush par défaut** sur tous les composants
- helpers réactifs supplémentaires pour réduire les ponts signaux ↔ RxJS
- meilleure interop entre Signal Forms et Reactive Forms pour migration progressive

### 2.6 Écosystème et outillage

- **Vitest** est devenu le testeur par défaut depuis Angular 21
- **Angular ARIA** : nouveaux primitives pour l'accessibilité (focus management, live regions)
- documentation `angular.dev` rafraîchie
